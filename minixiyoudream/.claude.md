## 1. 项目基础

### 技术栈
| 类别 | 技术 | 版本 |
|------|------|------|
| 框架 | React | 19.x |
| 语言 | TypeScript | 5.8.x (严格模式) |
| 构建 | Vite | 6.x |
| 状态 | Preact Signals | 2.x |
| 存储 | Dexie.js | 4.x |
| 样式 | Tailwind CSS | 4.x |
| 图标 | Lucide React | latest |
| 随机 | 自定义 PRNG | Mulberry32 |

### 目录结构
```
src/
├── types/          # TypeScript 类型定义
├── constants/      # 游戏配置数据（种族、门派、技能等）
├── signals/        # Preact Signals 状态管理
├── utils/          # 工具函数（PRNG、计算公式等）
├── db/             # Dexie.js 数据库（存档系统）
├── services/       # 业务逻辑服务层
├── hooks/          # 自定义 React Hooks
├── components/     # React 组件
│   ├── common/     # 通用组件
│   ├── character/  # 角色创建
│   ├── battle/     # 战斗系统
│   ├── inventory/  # 背包装备
│   ├── map/        # 地图系统
│   ├── pet/        # 宠物系统
│   └── dungeon/    # 副本系统
└── styles/         # 全局样式
```

### 常用命令
```bash
pnpm dev        # 启动开发服务器 (localhost:3000)
pnpm build      # 构建生产版本
pnpm typecheck  # TypeScript 类型检查
pnpm lint       # ESLint 代码检查
```

## 2. 宪法核心摘要

> 完整宪法请查阅 CONSTITUTION.md，以下是快速参考：

| 规则 | 核心约束 | 禁止行为 |
|------|----------|----------|
| **类型安全** | 显式类型，类型守卫 | `any`, 类型断言 |
| **Signals** | 跨组件状态用 Signals | useState 管理全局状态 |
| **确定性随机** | 使用 PRNG 实例 | `Math.random()` |
| **数据持久化** | Dexie + 版本迁移 | 直接操作 IndexedDB |
| **简单性** | YAGNI，函数优先 | 过早抽象，过度设计 |
| **组件设计** | 展示/容器分离，<200行 | 单文件巨型组件 |
| **数值设计** | 常量提取，配置驱动 | 硬编码魔法数字 |
| **单机化** | 离线可用，本地存档 | 网络依赖 |
| **性能** | 细粒度更新，虚拟列表 | setInterval 动画 |
| **错误处理** | Error Boundary，优雅降级 | 静默失败 |

## 3. AI 协作指令

### 3.1 添加新功能时
```
1. 阅读 CONSTITUTION.md 确认约束
2. 阅读相关设计文档 (docs/*.md)
3. 阅读相关现有代码 (src/types/, src/constants/)
4. 提出架构方案，说明设计决策
5. 获得确认后开始实现
```

### 3.2 编写代码时
```
1. 类型定义 → src/types/
2. 游戏配置 → src/constants/
3. 状态管理 → src/signals/
4. 业务逻辑 → src/services/
5. UI组件 → src/components/
```

### 3.3 工具选择规范

| 场景 | 推荐工具 | 说明 |
|------|----------|------|
| **创建新文件** | Write | 单个文件直接创建 |
| **修改现有文件** | Edit | 精确替换，避免全文件覆盖 |
| **安装依赖** | Bash | `pnpm add xxx` |
| **运行命令** | Bash | build, typecheck, lint |
| **复杂组件开发** | Task(general-purpose) | 多文件、复杂逻辑 |
| **代码结构探索** | Task(Explore) | 理解现有代码 |
| **架构方案设计** | Task(Plan) | 进入 Plan 模式 |
| **查阅技术文档** | MCP web_reader | 读取网页内容 |
| **分析 UI 设计稿** | MCP analyze_image | 图片分析 |

### 3.4 代码审查清单
- [ ] 无 `any` 类型
- [ ] 跨组件状态使用 Signals
- [ ] 随机操作使用 PRNG
- [ ] 数值使用常量配置
- [ ] 组件 < 200 行
- [ ] 错误有友好提示

## 4. Git 规范

### Commit Message
```
<type>(<scope>): <subject>

# 示例
feat(battle): 添加回合制战斗核心逻辑
fix(player): 修复HP计算溢出问题
docs(readme): 更新安装说明
refactor(signals): 重构状态管理结构
```

### Type 说明
| Type | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档更新 |
| `refactor` | 重构 |
| `style` | 格式调整 |
| `perf` | 性能优化 |
