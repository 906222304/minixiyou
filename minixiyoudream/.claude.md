|------|------|------|
| 框架 | React | 19.x |

## 目录结构
```
src/
├── types/          # TypeScript 类型定义
├── constants/      # 游戏配置数据
├── signals/        # Preact Signals 状态管理
├── services/       # 业务逻辑服务层
├── components/     # React 组件
├── db/             # Dexie.js 数据库
└── styles/         # 全局样式

.specify/           # Spec-Kit 工作流配置
├── memory/         # 项目原则和记忆
│   └── constitution.md
└── templates/      # 规格模板
    ├── spec-template.md
    ├── plan-template.md
    └── task-template.md

specs/              # 功能规格文档（按分支组织）
└── [branch-name]/
    ├── spec.md     # 功能规格
    ├── plan.md     # 技术计划
    └── tasks.md    # 任务清单
```

## 核心规范
- 使用 Preact Signals 管理全局状态
- 配置数据放在 src/constants/
- 业务逻辑放在 src/services/
- 类型定义放在 src/types/

## Spec-Driven Development 工作流

开发新功能时，遵循以下工作流：

### 1. Specify（规格定义）
创建 `specs/[feature-name]/spec.md`，定义：
- 功能目标和范围
- 用户故事
- 验收标准
- 数据需求

### 2. Plan（技术规划）
创建 `specs/[feature-name]/plan.md`，规划：
- 模块划分
- 数据流设计
- 接口定义
- 实现步骤

### 3. Tasks（任务分解）
创建 `specs/[feature-name]/tasks.md`，分解：
- 具体实现任务
- 任务依赖关系
- 验收标准
- 进度追踪

### 4. Implement（实现）
按任务顺序实现：
1. 类型定义 (types/)
2. 配置数据 (constants/)
3. 状态管理 (signals/)
4. 业务服务 (services/)
5. UI 组件 (components/)

### 5. Test（测试验证）
- TypeScript 类型检查
- 功能验证
- 边界测试

### 6. Maintain（维护）
- 更新相关文档
- 代码优化
- 版本记录

## 模板使用

复制模板开始新功能开发：
```bash
# 创建新功能规格目录
mkdir -p specs/[feature-name]

# 复制模板
cp .specify/templates/spec-template.md specs/[feature-name]/spec.md
cp .specify/templates/plan-template.md specs/[feature-name]/plan.md
cp .specify/templates/task-template.md specs/[feature-name]/tasks.md
```

## 项目原则

详见 [.specify/memory/constitution.md](.specify/memory/constitution.md)

核心原则：
- 类型安全：禁止 any，显式类型定义
- 状态管理：Preact Signals 管理全局状态
- 随机数：使用 PRNG，禁止 Math.random()
- 配置驱动：禁止硬编码魔法数字
- 组件设计：单文件 < 200 行
- 单机优先：离线可用，本地存档
